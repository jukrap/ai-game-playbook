# 엔진 지원

> 상태: Godot, Unity, Unreal Engine을 공식 어댑터 대상으로 계획합니다. 아직 어떤 실엔진 기능도 `planned`보다 높은 등급에 도달하지 못했습니다.

[English](engine-support.md) · [문서 안내](README.ko.md)

## 현재 표

| 엔진 | 정적 프로젝트 검사 | 엔진별 공개 보고 | 실제 에디터·런타임 | 현재 등급 |
| --- | --- | --- | --- | --- |
| Godot | 표식, 프로필, 버전 힌트, 정확한 회색상자 소스 무결성 | 상태와 예정 작업 14개 | 사용할 수 없음 | `planned` |
| Unity | 표식, 프로필, 잠금 파일 신호 | 사용할 수 없음 | 사용할 수 없음 | `planned` |
| Unreal Engine | 표식과 프로필 | 사용할 수 없음 | 사용할 수 없음 | `planned` |

정적 검사는 프로젝트 후보를 찾고 부족한 조건을 보고합니다. 설치된 실행 파일, 실행 중인 에디터, 플레이 화면, 대상 빌드가 확인됐다는 뜻은 아닙니다.

## 공통 계약

각 어댑터는 다음 작업을 지원하거나 지원하지 않는다고 명시해야 합니다.

`detect → negotiate → inspect → mutate → save → compile/import → test → play → deterministic input → logs → capture → profile → build/export → rollback`

모든 작업은 실행 방식, 필요한 권한, 가능한 효과, 제한, 부족한 증거, 지원 등급을 보고합니다. 지원하지 않는 작업을 워크플로에서 조용히 빼지 않고 기능 저하 상태로 드러냅니다.

## 증거 기준

| 등급 | 최소 조건 |
| --- | --- |
| `planned` | 작업 계약과 알려진 미충족 조건 |
| `detected` | 정확한 프로젝트, 엔진 실행 파일, 버전, 호환 환경 식별 정보 |
| `headless` | 에디터가 필요 없는 필수 검증과 테스트를 실행하고 제한된 로그·영수증 보존 |
| `editor-preview` | 정확한 에디터 세션 하나가 작업을 수행하고 에디터 결합 증거 생성 |
| `verified` | 결정적 게임플레이와 대상 빌드·내보내기가 실행 화면·산출물 출처 정보와 함께 통과 |

등급은 특정 환경의 특정 기능에 붙습니다. 스크립트 검증은 `headless`여도 입력 재생이나 실행 화면 캡처는 `planned`일 수 있습니다.

## Godot

현재 공개 경로는 Godot 프로젝트 후보 하나를 검사하고, major·minor 버전 힌트를 고정 목표 `4.7.2`와 비교한 뒤 공통 작업 목록을 보고합니다. 모든 작업은 계속 계획 단계입니다.

저장소에는 정확한 매니페스트로 고정한 Godot `4.7.2` 회색상자 프로젝트 소스도 있습니다. 정적 검사기는 고정된 파일과 해시, 프로젝트·씬 설정, 스크립트, 복사한 시나리오, 재생 진입점, `planned` 지원 상태를 함께 확인합니다. 별도의 제한형 기록 해석기는 고정 호출, 시나리오 식별 정보, 모든 판정 지점, 시점, 상태 필드와 해시, 마지막 이벤트, 프로세스 종료가 서로 맞는지 검사합니다. 이들은 구현·정적 증거와 `liveValidated: false`를 만들지만, Godot이 프로젝트를 해석·시작·플레이·캡처·저장·내보내기 할 수 있다는 증거는 아닙니다.

비공개 기반은 좁은 호스트 도구 권한을 받은 뒤 제한된 실행 파일 후보를 찾고 정확한 버전을 확인합니다. Windows 제공자는 폐기 가능한 검사와 고정 합성 실행으로 먼저 격리 정책을 검증합니다. 성공한 증명 하나는 정확한 읽기 전용 프로젝트·실행 파일 스냅샷에 묶을 수 있습니다.

버전이 `4.7.2`와 정확히 일치하면 별도 호스트 도구 승인을 받은 일회성 비공개 실행부가 이 입장권을 소비할 수 있습니다. 승인된 프로젝트와 실행 파일을 폐기 가능한 루트에 복사하고, 역량이 없는 AppContainer 안에서 고정된 헤드리스 기본 씬 호출만 실행합니다. 프로세스 하나와 시간·출력 한도를 강제하고, 경로 없는 보고와 `RunReceipt`를 보존합니다. 버전 불일치, 오래된 식별 정보, 복사한 권한, 한도 초과는 모두 안전하게 차단합니다. 성공과 고장 경로는 전용 시험 실행 파일로 통과했지만 설치된 Godot 배포본이나 회색 상자 프로젝트는 아직 실행하지 않았습니다. 공개 CLI·MCP에는 노출하지 않으며 어떤 기능도 `planned`보다 높이지 않습니다.

첫 알파는 공통 회색 상자 프로젝트에서 전체 흐름을 통과해야 합니다. 먼저 스크립트 검사, headless 테스트, 실제 게임 시작을 확인합니다. 이어서 같은 입력으로 플레이를 재현하고 로그, 실행 화면, 저장·불러오기, 승리 상태, Windows 내보내기 결과를 남깁니다.

## Unity

현재 프로젝트 검사는 Unity 표식, 프로필, 정적 `Temp/UnityLockfile` 신호를 찾습니다. 프로세스가 살아 있다고 추정하거나 에디터 인스턴스를 고르지는 않습니다.

예정 어댑터는 정확한 프로젝트와 Editor 버전을 묶고 에디터 차선 하나만 사용해야 합니다. domain reload 뒤에는 연결을 복구해야 합니다. 실제 EditMode·PlayMode 결과를 읽고 Game View를 캡처하며 Windows x64 Development Build를 시작해야 합니다. 뷰포트 이미지나 바깥 도구의 성공 응답만으로는 부족합니다.

## Unreal Engine

현재 프로젝트 검사는 Unreal 프로젝트 표식과 프로필을 찾습니다. 에디터를 열거나 프로세스에 연결하거나 자산을 검사하지 않습니다.

예정 어댑터는 프로젝트에 묶인 에디터 자동화, 필요한 경우 Python, Automation Framework 결과, 빌드용 UAT·UBT를 사용합니다. 에디터 뷰포트, PIE, cook, package, 패키지 실행 증거를 구분해야 합니다. 자산이나 actor 삭제는 되돌릴 수 있는 트랜잭션이 필요합니다.

## 기능 저하와 중단 규칙

프로젝트, 실행 파일, 프로세스, 에디터 세션, 씬·월드 식별 정보가 없거나 바뀌면 어댑터를 멈춥니다. 예상하지 않은 변경 파일, 권한 부족, 예산 초과, 스키마 불일치, 불확실한 변경도 즉시 중단 사유입니다.

일치하는 에디터가 여러 개면 추측으로 하나를 고르지 않습니다. 관계없는 엔진 프로세스를 종료하거나 사용 중인 checkout을 바꾸지 않습니다. 결과가 불확실한 변경도 자동으로 다시 시도하지 않습니다.
