# 증거와 검증

> 상태: 영수증, 산출물, 결과 정규화, 엔진 중립 시나리오 기반은 구현했습니다. 공개 증거 조회·내보내기와 실엔진 검증은 아직 계획 단계입니다.

[English](evidence-and-verification.md) · [문서 안내](README.ko.md)

## 증거 등급

증거 강도는 엔진 지원 등급과 따로 기록합니다.

| 등급 | 의미 |
| --- | --- |
| `documented` | 계약이나 예상 동작을 문서로 정의함 |
| `implemented` | 해당 코드가 있고 구조 검사를 통과함 |
| `test-witnessed` | 자동 테스트가 동작을 실제로 관찰함 |
| `locally-executed` | 실제 로컬 도구나 프로세스가 결과를 만들고 보존함 |
| `engine-verified` | 정확한 엔진 시나리오가 완전한 식별·실행 증거와 함께 동작함 |

런타임은 증거 등급을 자동으로 올리지 않습니다. 스키마에 맞는 보고서라도 주장을 뒷받침할 근거가 약하면 현재 등급을 유지합니다.

## 실행 영수증

`RunReceipt`는 실행 하나를 프로젝트, 기능, 확정 워크플로, 명령 설명자, 처리기, 레지스트리, 입력, 권한, 시간, 결과, 산출물, 변경 파일, 복구 결과와 묶습니다.

영수증은 해시로 연결된 추가 전용 기록입니다. 현재 구현은 제한된 비공개 체인을 저장하고 다시 읽습니다. 승격한 산출물 객체도 보존합니다. 이 API는 아직 `agpb evidence` 명령으로 공개하지 않았습니다.

바깥 응답 성공과 내부 결과 성공을 별도 필드로 기록합니다. 취소, 종료 불확실, 롤백, 결과 뒤 실패도 그대로 남습니다.

## 재조정 영수증

불확실한 대상은 원래 영수증 기록을 고쳐서 복구하지 않습니다. 재조정은 별도 실행과 `RunReceipt`를 사용하며, 정확한 대상 체크포인트, 현재 저장소 헤드, 관찰한 대상 영수증 상태, 완전한 증거, 등록 권한, 대상 변경 효과 0을 하나로 묶습니다. 대상 영수증이 있다면 분리된 첫 성공 영수증 하나이고 그 안의 완전한 종료 산출물이 해당 증거와 일치할 때만 받습니다. 대상은 원래 시도와 영수증 체인 헤드를 유지하고 추가 전용 재조정 정보만 받습니다.

첫 공급자는 안정된 관리 팩 복구 종료만 인식합니다. 명령 단계에서 불확실해진 한 단계 대상을 명령 재실행 없이 종료할 수 있습니다. 증거가 불완전하거나 대상·영수증 상태가 달라졌거나 변경 효과가 0이 아니거나 지원하지 않는 워크플로 형태면 대상은 계속 불확실 상태로 남습니다. 공개 증거 조회와 더 넓은 재조정 공급자는 아직 계획 단계입니다.

## 세부 결과

결과 모델은 다음 상황을 구분합니다.

- 프로세스 시작·종료 실패
- 테스트 보고서 없음 또는 불일치
- 발견한 테스트 0개
- 모든 테스트 건너뜀
- 단언 실패
- 필수 테스트 ID 누락
- 통과 보고 뒤 프로세스 충돌
- 게임플레이, 캡처, 성능, 빌드, 롤백 결과

테스트 0개를 성공으로 보지 않습니다. 통과 보고서가 있어도 뒤에 발생한 프로세스 실패를 지우지 않습니다.

## 결정적 게임플레이 증거

재현 가능한 실행에는 프로젝트, 엔진과 버전, 빌드, 렌더러, 씬·맵, 카메라, 초기 상태, seed, 시간 기준, 고정 단계 입력, 예상 상태 판정이 필요합니다.

실행 화면을 캡처할 때도 실행, 입력, 상태, 엔진, 렌더러, 씬, 카메라, 파일 해시를 기록합니다. 에디터 뷰포트, 직접 상태 주입, 정적 이미지는 실제 플레이와 따로 표시합니다.

`PlaytestScenario` 계약은 상대 틱 입력, 상태 단언, 필수 산출물, 실행 예산의 범위를 제한합니다. 디지털 입력은 한 가지 표현만 허용하고 축 값은 길이가 제한된 10진 문자열로 기록합니다. 상태 값에도 자료형을 명시해 엔진마다 숫자를 다르게 직렬화하는 일을 막습니다. 스키마와 의미 검사는 모호한 시점, 순서가 뒤바뀌거나 중복된 입력, 정렬되지 않은 단언·증거 집합, 예산을 벗어난 틱을 거부합니다. 재사용하는 시나리오에는 특정 엔진 프로젝트의 식별 정보를 넣지 않습니다. 실행할 때 별도 `PlaytestScenarioBinding`이 시나리오 해시를 정확한 기능 계약과 프로젝트 프로필에 묶습니다.

Godot 재생 형식에는 등록된 정규화 기록 계약과 고정 호출 해시가 있습니다. 해석기는 크기와 줄 수를 제한하고, 같은 줄바꿈 방식과 정해진 머리말을 사용하는 JSON 줄만 받습니다. 중복 JSON 키, 선언하지 않은 출력, 빠지거나 반복된 판정 지점, 잘못된 시점·상태 필드·상태 해시, 시나리오 변경, 마지막 이벤트와 프로세스 종료의 모순을 거부합니다. 시간 초과나 취소로 끝난 프로세스가 재생 실패 종료 코드를 남겨도 게임플레이 실패로 바꾸어 기록하지 않습니다. 자동 시험이 확인한 것은 해석기와 계약의 동작이며, 설치된 Godot 실행 환경이 만든 기록은 아직 보존하지 않았습니다.

틱 처리 순서도 고정합니다. `warmupTicks`보다 앞선 틱에는 정해진 입력을 넣지 않으며 `warmupTicks`부터 입력할 수 있습니다. N번 틱의 입력은 순번대로 N번 시뮬레이션 직전에 적용합니다. `atTick` 판정은 해당 시뮬레이션 직후 한 번 확인합니다. `withinTicks` 판정은 `firstTick`부터 `lastTick`까지 양끝을 포함해 매 틱 직후 확인하고, 처음 조건을 만족한 시점에 성공합니다.

공통 회색 상자에는 성공, 실패, 재시작, 저장, 불러오기, 승리 상태 시나리오가 필요합니다. 같은 초기 상태와 입력을 반복했을 때 결과가 같아야 하며 다르면 차이를 보고합니다.

## 산출물 무결성

비공개 산출물 기반은 완성된 프로젝트 내부 파일을 콘텐츠 주소 객체로 복제하고 manifest와 영수증에 묶습니다. 다시 읽을 때 객체, manifest, 체인, 식별 정보, 바이트 예산을 검사합니다.

제한된 검사기는 UTF-8, 정규 JSON, non-interlaced PNG를 확인하고 선택적으로 `AssetProvenance`와 대조합니다. PNG가 실제 실행 화면인지, 엔진이 자산을 올바르게 가져왔는지, 제작에 쓸 준비가 됐는지는 증명하지 못합니다.

보존 기간, 정리, 과거 레지스트리 이전, 더 많은 형식, 공개 목록·조회·내보내기 명령은 아직 계획 단계입니다.

## 성능 증거

성능 주장에는 선언한 예산과 비교 가능한 기준선이 필요합니다. 대상 하드웨어, 운영체제, 엔진, 렌더러, 설정, 해상도, 빌드 종류, 씬, 카메라, 입력, seed, 준비 실행, 프로파일러, 표본 방식, 허용 오차를 기록합니다.

에디터와 패키지 실행 결과를 같은 값처럼 비교하지 않습니다. 필요한 경우 평균, 백분위수, 지속 최악 구간, 급등, 메모리, 할당, 불러오기 시간, 멈춤을 보고합니다. 같은 환경이나 예산이 없으면 결과는 `unverified`입니다.

## 골든 작업

공통 3D 회색 상자가 첫 엔진 공통 동작 목표입니다. 이동, 카메라, 충돌, 수집물, HUD 개수, 저장·불러오기, 승리 상태를 포함합니다.

[저장소의 핵심 시나리오](../golden/graybox/scenario.json)는 엔진에 종속되지 않는 이동, 카메라, 충돌, 수집물, HUD, 승리 상태 판정을 입력 순서, 예산, 필수 증거, 고정 해시와 함께 정의합니다. 자동 테스트가 확인하는 범위는 이 정의와 변경 감지뿐입니다. 어떤 엔진도 아직 이 검증 시나리오를 실행하지 않았으며, 실행 화면·저장 주기·패키지 빌드가 통과했다고 주장하지 않습니다.

[Godot 소스 매니페스트](../golden/graybox/godot/manifest.json)는 Godot `4.7.2` 프로젝트 소스를 이 시나리오에 묶습니다. 프로젝트 소스에는 이동·카메라 제어, 충돌 지형, 수집물 2개, HUD 개수 표시, 저장·불러오기, 승리 상태, 고정 틱 입력 재생, 판정 검사, SHA-256 상태 추적이 들어 있습니다. 정적 검사는 파일 누락·추가·순서 변경·내용 변경을 거부하고 필수 프로젝트·씬·스크립트·시나리오 구조를 확인합니다. 통과해도 `implemented` 정적 증거만 성립하며, Godot이 프로젝트를 해석하거나 실행한 적은 아직 없습니다.

각 어댑터는 같은 플레이어 시나리오를 실행하면서 엔진별 빌드·테스트 증거를 보존해야 합니다. 정적 씬, 컴파일 성공, 에디터 화면 캡처만으로 작업을 완료할 수 없습니다.

## 지원 판정

특정 기능에 필요한 모든 증거가 요구 등급으로 존재할 때만 지원을 올립니다. 식별 정보 누락, 불완전한 테스트, 실행 화면이 아닌 캡처, 빌드 시작 확인 불가, 롤백 누락은 명시적인 미충족 조건으로 남깁니다.

현재 공개 Godot 보고에는 `documented` 작업 항목과 정적 프로젝트 관찰만 있습니다. 별도 회색상자 무결성 보고는 공개 엔진 작업이 아니며 `implemented` 정적 증거만 담습니다. 어느 쪽도 실엔진 증거를 만들지 않습니다.
