# 보안과 권한

> 상태: 현재 공개 명령은 프로젝트를 변경하거나 네트워크를 사용하지 않습니다. 더 강한 변경·엔진 권한은 설계되어 있지만 공개 실행 경로가 없습니다.

[English](security-and-permissions.md) · [문서 안내](README.ko.md)

## 현재 공개 경계

공개 CLI 명령 9개는 모두 프로젝트 읽기 권한만 요구합니다. 설명자에 변경 파일과 변경 바이트를 0으로 선언합니다. 엔진 실행, 에디터 연결, 소프트웨어 설치, 외부 제공자 호출, 게시, 증거 내보내기를 하지 않습니다.

선택형 MCP 실행부도 읽기 전용입니다. 정규화한 프로젝트 하나를 묶고 생성된 도구 중 명시한 일부만 등록합니다. HTTP 전송은 지원하지 않습니다. MCP annotation은 설명용 힌트이며 실제 권한은 런타임 경계가 결정합니다.

비공개 쓰기·프로세스 기반이 있다고 해서 해당 효과가 공개되는 것은 아닙니다. 경로, 계획, 보고서, 생성된 설명자만으로 명령 승인을 우회할 수 없습니다.

## 권한 모델

예정된 권한 중개기는 다음 등급을 구분합니다.

| 등급 | 기본 결정 |
| --- | --- |
| 프로젝트 상태 읽기 | 선택한 프로젝트와 고정 예산 안에서 허용 |
| 승인된 기능 범위의 소스 변경 | 기능과 정확한 범위를 묶은 뒤에만 허용 |
| 에디터 제어 | 프로젝트와 세션마다 한 번 확인 |
| 승인된 테스트·빌드 실행 | 선언한 시간·출력·자원 예산 안에서 허용 |
| 설치, 네트워크, 외부 전송, 비용, 파괴, 게시, 출시 | 매번 확인 |

현재 공개 명령은 첫 행만 사용합니다. 나머지는 목표 정책이며 지금 CLI에서 사용할 수 있다는 뜻이 아닙니다.

승인은 프로젝트, 명령, 요청, 범위, 예산, 만료 시각과 필요한 기능·워크플로·에디터 세션을 묶습니다. 한 목적에만 쓸 수 있으며 복사한 데이터로 이전할 수 없습니다.

## 승인 표시 경계

제어부에는 이제 호스트에 종속되지 않는 내부 `ApprovalPrompt` 계약이 있습니다. 앞으로 승인 화면을 제공할 호스트가 서명을 요청하기 전에 보여줘야 할 프로젝트, 명령, 레지스트리, 입력 해시, 범위, 예산, 제한 시각, 권한 방식, 안정적인 영향 분류를 정확히 담습니다.

이 표시 객체에는 명령 원문 입력, 프로젝트 절대 경로, 자격 증명, 서명, 승인 키를 넣는 필드가 없습니다. 표시 내용 해시는 승인 범위가 달라졌는지 확인할 뿐 실행 권한이 아닙니다. 스키마를 통과한 직렬화 복사본은 화면에 표시할 수 있지만, 서명 전 승인 본문을 만들 수 있는 중개기 challenge와 연결되는 것은 같은 프로세스의 원본 표시 객체뿐입니다. 만들어진 승인 본문도 신뢰 키의 서명과 중개기의 정확한 검증을 거쳐야 합니다.

핵심 실행부에는 한 번만 정산하는 내부 승인 세션도 있습니다. 직렬화할 수 있는 세션 요청은 호스트 식별자 하나, 표시 내용과 실행 요청의 해시, 표시 제한 시각, 승인 증명의 만료 시각과 사용 횟수를 정확히 묶습니다. 호스트 응답은 해당 세션의 승인·거부·취소 중 하나만 표현합니다. 명령 입력, 승인 증명, 서명, 키 정보는 담지 않습니다. 호스트에는 검증한 읽기 전용 표시 복사본만 전달하고, 원래 요청·표시 권한·권한 중개기 연결은 같은 프로세스의 원본 세션만 보유합니다.

승인 응답을 받아들인 세션은 대기 상태로 돌아가지 않습니다. 외부 서명기는 각 승인 증명의 정확한 해시만 받고, 서명된 결과는 원래 권한 중개기가 실행 요청 전체와 다시 대조합니다. 거부·취소·만료 때는 서명기를 호출하지 않습니다. 승인을 받아들인 뒤 서명기나 중개기 검증이 실패하면 해당 세션을 실패로 끝내며, 다시 시도하려면 새 세션과 새 결정이 필요합니다. 호스트 자체의 도구 확인 창과 앞으로 연결할 MCP 입력 요청은 표시 단계의 추가 방어선일 뿐 이 승인 검사를 대신하지 않습니다.

비공개 Codex 어댑터에는 이 세션을 위한 같은 프로세스의 표시 포트가 있습니다. 호스트 콜백에는 읽기 전용 표시 객체와 취소 신호만 전달합니다. 응답의 세션 식별 정보와 해시는 어댑터가 직접 만들고, 세션마다 표시 하나만 진행할 수 있습니다. 서명기, 권한 중개기, 실행 요청 원문, 원본 세션 핸들은 표시 포트 밖에 둡니다. 호출자 취소, 표시 만료, 호스트 실패, 잘못된 결정은 모두 서명 없이 끝냅니다. 호스트 실패와 잘못된 출력은 세션도 닫은 뒤 제한된 오류만 반환합니다.

핵심 실행부에는 메모리에서만 쓰는 비공개 로컬 서명기도 있습니다. 호출자가 직접 건넨 정규 형식의 암호화되지 않은 PKCS#8 Ed25519 키만 가져오고, 권한 중개기가 신뢰할 SPKI 공개키는 그 개인 키에서 파생합니다. 서명기 사용권은 최대 5분, 서명 32회로 제한합니다. 정규 승인 해시와 실제 취소 신호만 받으며 키와 별도로 닫을 수 있습니다. 키를 닫으면 남은 모든 서명기 사용권을 차단하고 보관하던 키 객체 참조를 놓습니다. 메모리가 완전히 지워졌다고 주장하거나 이미 반환한 서명을 회수하지는 않습니다.

범위 제한 서명 사용 경계는 콜백이 성공하거나 실패한 뒤 사용권을 닫습니다. 콜백 안에서 서명기를 반환하거나 보관하거나 직접 닫아도 경계가 끝난 뒤에는 다시 쓸 수 없습니다. 비공개 로컬 호스트 실행부는 원본 승인 세션에서 정확한 만료 시각과 서명 횟수를 가져와 표시와 최종 권한 판정을 이 범위 안에서 수행하고, 호출자 소유 키는 이후의 명시적 생명주기 결정을 위해 열어 둡니다.

비공개 관리 스킬 작업 하나는 준비 계획, 승인 세션, 프로젝트·실행 식별 정보, 서명 키 식별 정보를 같은 프로세스의 핸들에 묶습니다. 이 핸들에는 키, 실행 권한, 절대 경로, 옮겨 쓸 수 있는 권한 정보가 없습니다. 한 번만 호출할 수 있으며, 승인되면 같은 호출에서 정확한 계획을 곧바로 실행합니다. 거부·취소·만료, 복사한 핸들, 다른 키, 동시 호출, 반복 호출은 다음 변경 효과 전에 멈춥니다. 원래 작업은 자동으로 다시 시도하지 않습니다.

중단 뒤에는 범위가 제한된 읽기 전용 조회로 영속 워크플로의 최신 상태를 확인할 수 있습니다. 별도의 읽기 전용 복구 판단은 트랜잭션 기록과 프로젝트 상태를 두 번 비교하고, 검사 중 워크플로 상태가 바뀌면 결과를 거부합니다. 트랜잭션이 없다고 보고할 수는 있지만 원래 작업을 재개하거나 복구 결정을 쓰지는 못합니다. 복구 확정은 별도 승인을 요구하는 내부 워크플로로 남습니다.

프로젝트 초기화도 별도 작업 유형으로 같은 일회성 호스트 규칙을 사용합니다. 고정 구성 계획과 정확한 키 ID·지문을 묶고, 어떤 파일도 쓰기 전에 승인을 표시하며, 승인 직후 곧바로 실행합니다. 승인 대기 구간은 30초 실행 예산과 분리합니다. 충돌한 계획은 작업이 될 수 없고, 이미 초기화된 프로젝트는 승인이나 변경 권한 없이 할 일 없음으로 끝납니다.

초기화와 관리 스킬 설치는 승인이나 실행 식별 정보를 공유하지 않습니다. 깨끗한 프로젝트에서는 초기화를 먼저 끝낸 다음 새로운 스킬 계획을 준비하고 설치 승인을 따로 받습니다. 초기화 복구 검사는 읽기 전용이며 정확한 실행 하나를 골라 제한된 판단을 두 번 수행하고, 그 사이 상태가 바뀌면 실패합니다. 복구 확정을 실행할 수는 없습니다.

승인 대기와 실행 시간은 서로 다른 상한을 사용합니다. 명시적 승인이 필요한 요청은 등록된 실행 시간에 더해 최대 5분의 승인 대기시간을 가질 수 있습니다. 자동 권한 요청에는 추가 시간이 생기지 않습니다. 승인이 끝난 뒤 실행 권한은 승인 만료, 요청의 절대 deadline, 승인 시각에 실행 예산을 더한 시각 중 가장 빠른 때 종료됩니다. 따라서 승인 대기가 실행 예산을 몰래 소모하거나 늘리지 않습니다.

실행부는 서명 키를 만들거나 파일에서 읽거나 파일에 쓰거나 영속 저장하지 않습니다. 키 경로와 개인 키 내용은 표시 포트, 승인 표시, 세션 데이터, 상태 요약, 영수증, 제한된 오류에 들어가지 않습니다. 영속 키 저장, 교체, 백업, 운영체제 접근 제어는 아직 구현하지 않았습니다.

이 구성은 내부 연동 경계일 뿐 사용자 화면이나 MCP 입력 요청 구현이 아닙니다. 승인 내용을 보여주거나 결정을 받는 공개 명령은 없고, 읽기 전용 MCP 도구 목록도 바뀌지 않았습니다. 비공개 호스트 경로는 프로젝트 초기화와 관리 스킬 추가를 서로 다른 승인·실행 작업과 읽기 전용 복구 검사로 책임집니다. 공개 초기화·설치·복구는 계속 닫혀 있으며, 실제 복구 실행은 별도의 내부 승인을 거쳐야 하고 이 호스트 경로에서는 호출할 수 없습니다.

## 중단 조건

다음 조건이 생기면 새 효과를 일으키기 전에 실행을 멈춥니다.

- 일치하는 프로젝트나 에디터가 둘 이상임
- 프로젝트, 실행 파일, 프로세스 시작, 세션, 씬, 월드, 레지스트리, 명령, 처리기 식별 정보가 달라짐
- 예상하지 않은 변경 파일이 생김
- 필요한 권한이 없거나 만료됨
- 시간, 출력, 파일, 바이트, 복구 횟수, 메시지 예산을 넘음
- 대상이 링크, 대소문자 별칭, 프로젝트 밖, 잘못된 형식, 크기 초과이거나 계획 뒤 바뀜
- 프로세스나 변경 결과를 확실하게 정산할 수 없음

결과가 불확실한 변경은 다시 시도하지 않습니다. 먼저 영속 체크포인트와 실제 프로젝트 상태를 검사합니다.

## 파일시스템과 관리 콘텐츠

프로젝트 경로를 정규화하고 묶인 루트 안인지 확인합니다. 링크 경로, 상위 이동, 대소문자 별칭, 예상하지 않은 파일 형식, 식별 변경은 안전하게 차단합니다. 비교 후 교체 쓰기는 커밋할 때 관찰한 이전 내용이 그대로여야 합니다.

관리 팩은 소유 파일과 디렉터리를 정확히 선언합니다. 안정된 설치 상태는 마지막에 커밋합니다. 명확한 실패는 확인된 쓰기를 역순으로 되돌리고, 불확실한 효과는 검사할 수 있도록 트랜잭션 표식을 남깁니다. 제거할 때 소유하지 않은 파일을 건드리면 안 됩니다.

현재 `pack list`, `pack doctor`, `skill check`, `init`은 이 상태를 검사하거나 계획만 합니다.

## 내부 복구 종료

내부 워크플로 하나가 이미 검사한 관리 팩 트랜잭션을 종료할 수 있습니다. 복구 실행에는 별도 실행 식별 정보를 사용하며, 승인·차선 소유권·체크포인트·영수증에 기존 트랜잭션 식별 정보를 재사용하지 않습니다. 기존 식별 정보는 원래 저널과 활성 표식에만 묶입니다.

런타임은 승인 전에 정확한 보고서를 다시 검사하고, 효과를 일으키기 전에 시작 체크포인트를 저장하며, 실제 종료 또는 조정 기록을 내용 주소형 증거로 보존합니다. 성공하려면 종료 기록, 영수증, 최종 체크포인트가 모두 일치해야 합니다. 효과 경계를 지난 뒤 실패하면 결과를 불확실한 상태로 유지합니다. 성공을 반환하지 않고 시작 체크포인트를 남긴 뒤 차선을 해제하며, 자동으로 다시 시도하지 않습니다.

이 워크플로는 내부용입니다. CLI나 MCP에서 팩 추가·갱신·제거, 스킬 설치, 복구 기능을 사용할 수 있게 만들지는 않습니다.

## 내부 증거 재조정

팩 복구 변경은 끝났지만 뒤이은 증거 승격이 끊기면, 별도 내부 워크플로가 남아 있는 불확실 체크포인트, 현재 체크포인트 헤드 기록, 대상 영수증 상태, 안정된 저널 종료를 검사할 수 있습니다. 새 계획을 만들고 메타데이터 쓰기 승인, 프로젝트 쓰기 차선, 실행 식별 정보, 영수증을 모두 새로 요구합니다. 원래 명령은 다시 실행하지 않습니다.

완전한 증거 하나, 대상 식별 정보, 현재 저장소 헤드, 관찰한 영수증 상태, 등록 명령, 변경 효과가 0인 새 영수증이 모두 일치해야 재조정에 성공합니다. 대상 영수증이 없으면 없다는 상태를 기록합니다. 있다면 해당 명령의 분리된 첫 성공 영수증 하나여야 하며, 그 안의 완전한 종료 산출물이 현재 증거와 정확히 일치해야 합니다. 대상 체크포인트에는 추가 전용 재조정 정보를 붙여 종료하고, 원래 시도 목록과 영수증 체인 헤드는 그대로 둡니다. 상태 변화, 복사한 계획, 불완전한 증거, 달라졌거나 모순되는 대상 영수증, 프로젝트 변경 효과가 하나라도 있으면 멈춥니다.

이 경로는 모든 복구를 우회하는 수단이 아닙니다. 공통 계약은 증명된 `succeeded` 또는 `failed` 대상을 표현할 수 있지만, 현재 팩 복구 공급자는 완료된 종료를 증명한 뒤 `succeeded`만 만듭니다. 첫 버전은 이 한 단계 명령 상태만 지원합니다. 롤백, 여러 단계, 프로세스, 에디터, 실엔진 효과는 재조정하지 않으며 공개 CLI·MCP·호스트 변경 표면도 없습니다.

## Windows 격리 검증

소스에서 빌드하는 Windows x64 격리 패키지는 자체 검사 증명을 만들기 전에 네이티브 산출물 하나를 검증합니다. 고정된 패키지 위치의 일반 x64 PE 파일만 허용하고, 실행 전후 해시를 확인하며, 네이티브 호스트가 격리된 실행 파일을 준비하는 동안 열린 산출물의 동일성을 유지합니다.

네이티브 검사는 폐기 가능한 비공개 검사 환경과 역량을 하나도 부여하지 않은 AppContainer 프로필을 만듭니다. 파일 생성·교체·제거·이름 변경·하드 링크 별칭, 소유한 IPv4·IPv6 TCP 수신점과 로컬 UDP 접근, 일반·분리 자식 프로세스가 모두 차단되는지 확인합니다. Job Object의 활성 프로세스 한도 1, 핸들을 닫을 때의 프로세스 종료, 검사 환경과 프로필의 정확한 정리도 검사합니다. 격리된 네트워크 검사 전에 로컬 수신점이 실제로 열려 있는지 대조하며, 외부 주소와 사용자 프로젝트 파일은 사용하지 않습니다.

TypeScript 경계는 산출물·설명자·로컬 목록·프로젝트 식별 해시·임의 확인값·기한을 한 번만 쓸 수 있는 동일 프로세스 핸들에 묶습니다. 네이티브 JSON 보고서는 스키마를 검사하며, 검사를 실행한 프로세스 안에서만 수명이 짧은 증명을 만들 수 있습니다. 직렬화한 보고서, 다시 만든 객체, 복사한 증명, 만료된 핸들, 산출물 변경, 정리 불확실, 실패한 검사에는 권한이 없습니다.

방금 만든 증명 하나는 비공개 합성 실행 경로에서 한 번만 사용할 수 있습니다. 이 경로는 새 프로젝트·실행 파일 스냅샷에 경로를 넣지 않고, 호출과 결정적 출력을 미리 고정하며, 프로세스 하나를 최대 10초·출력 64 KiB로 제한합니다. 네이티브 호스트는 실행 전후에 산출물과 스냅샷을 다시 확인합니다. 내부 작업은 현재 토큰이 AppContainer가 아니면 직접 실행되기를 거부하고, 폐기 가능한 프로필 안에 예상한 결과 하나만 씁니다. 임의 명령·환경·네트워크 대상·실행 파일·사용자 프로젝트 경로는 받을 수 없습니다. 성공하려면 종료 코드 0, 전체 프로세스 1개와 활성 프로세스 0개, 일치하는 출력 해시, 보존된 스냅샷, 확인된 종료, 완전한 프로필·검사 환경 정리가 모두 필요합니다.

실패와 정산 불확실은 구분합니다. 프로세스 종료를 확인하지 못했거나 실행 뒤 스냅샷을 읽을 수 없거나 산출물이 바뀌었거나 네이티브 결과가 잘못됐거나 정리가 불확실하면 실행 권한을 만들지 않으며 성공으로 올리지 않습니다.

성공한 합성 실행 증명 하나는 짧은 수명의 엔진 입장권을 만드는 데 한 번만 쓸 수 있습니다. 입장권은 같은 프로세스의 정확한 프로젝트 루트와 실행 파일 권한을 다시 확인하고, 제한된 프로젝트 소스를 두 번 검사하며, 링크와 이식 가능한 경로 충돌을 거부한 뒤 경로를 담지 않는 해시를 작업 하나와 호출 하나에 묶습니다. 고정된 로컬 상태 디렉터리는 제외하지만 소스나 실행 파일이 바뀌면 입장권은 무효가 됩니다.

정확한 버전의 Godot 준비 상태는 이 입장권을 승인에 묶인 일회성 엔진 실행으로 바꿀 수 있습니다. 비공개 네이티브 호스트는 같은 프로세스의 전달 권한으로만 원본 위치를 받고, 정확히 승인된 프로젝트 목록과 실행 파일을 폐기 가능한 루트에 복사합니다. 역량이 없는 AppContainer에는 이 복사본만 읽고 실행할 권한을 줍니다. 프로세스 하나로 제한한 Job Object, 고정 헤드리스 인자, 출력·시간 한도를 사용하며, 환경 권한을 물려주거나 네트워크 역량을 부여하지 않습니다. 공개 요청·보고·영수증에는 원본 경로나 로그 본문이 없습니다.

호출자 취소는 실행·요청·산출물·새 취소 식별 정보에 묶인 별도의 제한형 네이티브 제어 호출로 전달합니다. 이 호출은 일치하는 로컬 실행에만 신호를 보낼 수 있습니다. 주 제공자는 계속 살아서 실행 중인 프로세스가 있으면 Job Object를 종료하고, 원본을 다시 검사하며, AppContainer 프로필과 폐기 루트를 제거한 뒤 최종 보고를 만듭니다. 신호 확인과 정리가 모두 끝난 경우만 `cancelled`로 기록합니다. 신호를 확인하지 못했거나 종료를 확정하지 못했거나 원본이 달라졌거나 정리가 끝나지 않으면 실패 또는 불확실입니다. 비상 한도 안에 정산되지 않는 제공자는 상위 호스트가 강제로 멈출 수 있지만, 그 실행은 신뢰할 수 있는 취소 보고를 반환할 수 없습니다.

호스트는 실행 뒤 원본 식별 정보를 다시 확인합니다. 원본 상태 변화, 종료 불확실, 불완전한 정리, 예상하지 않은 복사본 변경, 프로필 증가량 초과, 출력 초과, 모순된 네이티브 보고는 실패나 불확실로 판정합니다. 성공, 제한된 고장, 엔진 시간 초과, 실행 중 호출자 취소를 전용 시험 실행 파일로 검증했습니다. 설치된 Godot 결과나 실엔진 지원 등급을 성립시키지 않습니다.

## 프로세스와 에디터

프로세스 권한은 실행 파일 내용과 식별 정보, 시작 정보, 프로젝트, 명령, 정책, 예산을 함께 묶습니다. PID, 프로세스 이름, 포트, 창 제목만으로는 부족합니다.

출력, 실행 시간, 자식 프로세스, 취소, 종료 정산에 상한을 둡니다. 프로세스 성공이 내부 테스트나 게임플레이 성공을 뜻하지 않습니다. 에디터 작업은 프로젝트마다 차선 하나를 사용하며 다시 불러오거나 재시작한 뒤 정확한 세션 식별 정보를 요구합니다.

공개 런타임이 사용하는 컴파일된 격리 제공자 목록은 아직 비어 있습니다. 비공개 Godot 경로는 원본 동일 프로세스 핸들과 별도 승인이 있어야만 접근할 수 있으며, 공개 CLI나 MCP 작업으로 등록하지 않았습니다. 따라서 공개 Godot 시작은 실행 전에 계속 차단됩니다.

## MCP 제한

STDIO 실행부는 읽지 않은 입력, 누적 원시·해석 입력, 직렬화 출력, 전체 메시지, 미응답 요청 수를 제한합니다. 제한 시간과 취소 뒤에는 정해진 시간 안에 정산되기를 기다립니다. 처리기가 정산되지 않으면 해당 계획을 차단하고 진행 중인 같은 실행을 취소합니다.

현재 MCP는 명시적으로 고른 읽기 전용 도구만 노출합니다. 변경, 외부 제공자, 실행 파일, 에디터 제어, 네트워크 경로는 없습니다.

## 네트워크, 외부 제공자, 사용 정보

사용 정보 수집 기능은 없습니다. 프로젝트 증거를 밖으로 보내는 경로는 앞으로 만들 명시적 내보내기 명령뿐입니다.

네트워크 접근, 외부 전송, 유료 제공자 호출에는 별도 승인이 필요합니다. 앞으로 제공자 기능을 만들 때는 전송 전에 목적지, 데이터, 모델·체크포인트, 예상 비용, 권리 정보를 보여줘야 합니다. 외부 제공자는 기본으로 끕니다.

## 비밀 정보와 로그

비밀 정보와 컴퓨터별 설정은 로컬에 두고 Git에서 무시합니다. 로그와 영수증에는 식별 정보, 해시, 제한된 진단, 가린 오류 문맥만 기록해야 합니다. 자격 증명이나 제한 없는 파일 내용을 남기면 안 됩니다.

공개 문서와 생성된 상태에는 로컬 경로, 비공개 진단, 비밀 정보를 넣지 않습니다.
