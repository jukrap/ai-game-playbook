# 스킬

> 상태: 역량 중심 스킬 12개를 패키지하고 레지스트리에 연결했으며, 하나의 실험적 관리 팩이 파일 해시와 소유 범위를 증명합니다. 스킬은 작업 방법만 안내하며, 공개 설치 기능이나 실행 권한은 아직 없습니다.

[English](skills.md) · [문서 안내](README.ko.md)

스킬은 반복되는 게임 개발 작업을 위한 작고 단계적으로 불러오는 작업 지침입니다. 에이전트가 필요한 질문을 하고, 제약을 지키며, 알맞은 증거를 요구하도록 돕습니다. 스킬 자체는 권한을 주지 않으며 엔진 기능이 실제로 존재한다는 증명도 되지 않습니다.

## 선택 방법

- 작업을 충족하는 최소 스킬만 고릅니다. 보통 1개에서 5개면 충분합니다.
- 플레이어에게 보이는 결과를 먼저 정하고, 조건이 맞을 때만 안전·검증 스킬을 더합니다.
- 한 번에 적용하는 검토 관점은 3개를 넘기지 않습니다.
- 엔진 기능이 필요한 작업은 먼저 프로젝트를 검사합니다.
- 필요한 기능, 식별 정보, 예산, 권한, 증거를 확인할 수 없으면 멈춥니다.

## 현재 목록

| 스킬 ID | 사용 목적 |
| --- | --- |
| `project.inspection` | 프로젝트를 식별하고 정적 엔진 기능의 미충족 조건 보고 |
| `feature.contract-planning` | 제한된 플레이어 결과, 변경 범위, 예산, 롤백 정의 |
| `gameplay.vertical-slice` | 하나의 종단 간 게임플레이 조각을 계획하고 검증 |
| `save-load.integrity` | 버전이 있고 원자적이며 복구 가능한 저장 동작 설계 |
| `ui.game-qa` | 상태, 입력, 배치, 언어, 접근성을 아우르는 HUD·게임 UI 검토 |
| `playtest.deterministic` | 재현 가능한 플레이 입력, 상태, 테스트, 실행 증거 정의 |
| `evidence.support-review` | 증거가 기능이나 지원 등급을 뒷받침하는지 판정 |
| `performance.budget-review` | 명시한 예산과 같은 환경 기준선으로 실행 성능 비교 |
| `balance.deterministic-review` | 전투, 경제, 성장, 보상, 난이도 모델을 같은 조건에서 비교 |
| `asset.lifecycle` | 임시 자산이나 입력 자산을 출처 정보, QA, 승인 단계로 이동 |
| `build.export-readiness` | 도구 체인, 테스트, 산출물, 시작 동작, 로컬 빌드 준비 상태 검토 |
| `engine.change-safety` | 엔진 변경을 식별 정보, 권한, 실행 차선, 증거, 롤백으로 제한 |

실제로 엔진별 동작이 필요하지 않다면 공통 스킬을 사용합니다. Godot, Unity, Unreal 작업 스킬은 어댑터가 필요한 실행 권한과 증거를 제공할 때까지 계획 단계로 둡니다.

## 스킬이 할 수 있는 일

패키지 스킬은 사용 조건, 제외 조건, 작업 질문, 완료 기준, 증거 책임을 정의합니다. 런타임은 스킬을 노출하기 전에 frontmatter, 경로, 해시, 크기, 대상 이름, 레지스트리 경로가 맞는지 검사합니다.

스킬은 쓰기 승인, 에디터 선택, 프로세스 실행, 네트워크 접근, 도구 설치, 빌드 게시, 증거 등급 상향을 할 수 없습니다. 이런 작업에는 별도 런타임 기능과 권한이 필요합니다.

## 소스에서 검사하기

```bash
pnpm build
pnpm run agpb -- skill list --project <project-path>
pnpm run agpb -- skill check --project <project-path>
```

`skill list`는 스킬 본문이나 로컬 원본 위치를 노출하지 않고 제한된 목록 정보만 반환합니다. `skill check`는 고정된 프로젝트 대상을 누락, 현재, 충돌, 위험으로 구분합니다. 두 명령 모두 읽기 전용입니다.

## 설치 상태

런타임은 `.agents/skills/*/SKILL.md`를 두 단계에서 결정적으로 검사할 수 있습니다. 첫 단계는 후보 디렉터리와 파일 상태를 분류합니다. 두 번째 단계는 패키지 파일 해시, 프로젝트 식별 정보, 프로젝트 단계, 설치 상태, 각 스킬 디렉터리의 직접 소유권, 검사 한도를 묶는 비공개 관리 팩 사전 검사입니다. 두 준비 단계 모두 파일을 만들거나 바꾸거나 지우지 않습니다.

관리 팩은 공용 경로인 `.agents`와 `.agents/skills`를 소유하지 않습니다. 비공개 프로젝트 초기화 워크플로는 두 디렉터리를 소유권 없는 고정 대상으로 포함합니다. 기존 승인, 실행 차선, 롤백, 체크포인트, 영수증 경계 안에서 이 경로를 만들거나 그대로 유지할 수 있습니다. 공개 `agpb init`은 여전히 계획만 보고하고 적용하지 않습니다. 관리 팩 사전 검사를 실행할 때 공용 상위 경로가 없으면 충돌로 멈춥니다.

관리 소유권이 없는 기존 스킬 파일도 내용이 패키지와 같더라도 충돌로 처리합니다. 파일 내용이 같다는 이유만으로 사용자 파일을 넘겨받거나 덮어쓰지 않습니다.

비공개 팩 추가 경로는 새로 준비한 계획을 정확한 설치 승인, 하나의 프로젝트 쓰기 차선, 지속 워크플로 실행, 비교 후 교체 쓰기, 영수증, 내용 주소형 종료 트랜잭션 증거, 롤백, 복구 차단선에 연결합니다. 복사되거나 오래된 계획은 거부하고, 결과가 불확실한 변경은 자동으로 다시 시도하지 않습니다. 저장한 워크플로를 다시 읽었을 때도 `succeeded`여야만 성공을 반환합니다. 이 경로는 설치 수명주기를 검증하기 위한 내부 기반이며 공개 제품 표면은 아닙니다.

`agpb skill install`은 여전히 계획 단계입니다. 공개 설치에는 사용자가 확인할 수 있는 명시적 승인 흐름, 안정된 복구·종료 명령, 공개 명령 경계 전체를 통과하는 중단 테스트가 더 필요합니다. 이 조건을 통과하기 전에는 스킬 대상을 검사할 수만 있고 `agpb`로 설치할 수는 없습니다.
