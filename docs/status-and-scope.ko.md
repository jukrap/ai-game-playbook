# 현재 상태와 범위

> 상태: 소스에서 실행하는 초기 기반입니다. 공개 명령은 프로젝트를 변경하지 않으며, 비공개 Windows x64 격리 프로세스 경로는 시험 실행 파일로 검증했습니다. 모든 엔진 지원 등급은 `planned`이고 배포 패키지는 없습니다.

[English](status-and-scope.md) · [문서 안내](README.ko.md)

## 지금 되는 일

이 저장소는 비공개 pnpm 작업 공간과 `agpb` 실행 파일을 소스에서 빌드합니다. 현재 명령은 9개입니다.

| 명령군 | 현재 동작 |
| --- | --- |
| `init` | 파일을 쓰지 않고 고정된 프로젝트 내부 구성을 계획 |
| `doctor` | 런타임, 레지스트리, 프로젝트 상태, 관리 상태의 건전성 검사 |
| `project inspect` | 제한된 엔진 표식과 커밋된 프로젝트 프로필 읽기 |
| `pack list`, `pack doctor` | 설치된 팩의 식별 정보, 소유권, 변형, 복구 상태 검사 |
| `skill list`, `skill check` | 패키지 스킬 12개를 나열하고 고정 설치 대상 검사 |
| `engine status`, `engine capabilities` | Godot 프로젝트 정적 호환성과 예정 작업의 미충족 조건 보고 |

아홉 명령 모두 프로젝트 파일 쓰기, 엔진 실행, 에디터 제어, 네트워크 접근, 소프트웨어 설치를 하지 않습니다. 사람이 읽는 출력과 JSON 출력은 같은 검증 결과와 종료 분류를 사용합니다.

저장소의 Godot `4.7.2` 회색상자 프로젝트 소스에는 이동, 카메라, 충돌, 수집물, HUD 상태, 저장·불러오기, 승리 상태, 결정적 입력 재생, 상태 추적이 들어 있습니다. 정확한 매니페스트와 어댑터 테스트가 파일 목록, 해시, 시나리오 의미, 필수 구조, 고정된 `planned` 지원 상태를 함께 검사합니다. 별도의 제한형 해석기는 고정 재생 기록 형식, 판정 지점의 집합과 시점, 상태 해시, 마지막 결과, 프로세스 종료가 서로 맞는지 확인합니다. 이는 구현과 소스 무결성 증거일 뿐이며, 설치된 Godot이 프로젝트를 해석·실행하거나 재생 기록을 만든 적은 아직 없습니다.

타입이 있는 계약과 검증된 단일 레지스트리가 있습니다. 프로젝트·프로세스 제한, 권한·워크플로 상태, 영수증·산출물, 관리형 팩 트랜잭션도 기반으로 구현했습니다. 비공개 일회성 호스트 작업은 고정 제어 구성과 소유권 없는 공용 `.agents/skills` 상위 경로를 롤백·지속 증거와 함께 만들거나 유지할 수 있습니다. 패키지 스킬 12개는 파일 해시로 검증하는 하나의 실험적 팩에 묶었습니다. 두 번째 비공개 작업은 정확한 설치 승인, 오래된 계획 재검사, 하나의 프로젝트 쓰기 차선, 비교 후 교체 소유권, 체크포인트, 영수증, 내용 주소형 종료 트랜잭션 증거, 롤백, 복구 차단선까지 포함합니다. 읽기 전용 MCP 실행부와 쓰기 없는 호스트 설정 계획기도 있습니다. 위 공개 명령에서 노출하지 않는 부분은 제품 기능이 아니라 기반 구현으로 봅니다.

내부 복구 종료는 새 복구 실행과 기존 팩 트랜잭션의 식별 정보를 분리합니다. 새 승인을 요구하고, 프로젝트 쓰기 차선 하나에서 트랜잭션을 다시 검사하며, 저널 종료·내용 주소형 종료 증거·`RunReceipt`·최종 워크플로 체크포인트가 모두 일치할 때만 성공을 반환합니다. 트랜잭션을 닫은 뒤 증거 저장에 실패하면 성공을 반환하지 않고, 나중에 상태를 맞출 수 있도록 시작된 체크포인트를 남깁니다. 해당 변경을 자동으로 다시 시도하지 않습니다.

첫 내부 증거 재조정 공급자는 정확하고 안정된 종료 증거로 남아 있는 한 단계 팩 복구 체크포인트를 닫을 수 있습니다. 재조정에는 별도 실행·승인·영수증을 사용하고, 현재 체크포인트 헤드와 대상 영수증 상태를 관찰하며, 원래 시도나 대상 영수증 체인 항목을 새로 만들지 않습니다. 팩 변경도 다시 실행하지 않습니다. 이 공급자는 비공개이며 여러 단계, 롤백, 프로세스, 에디터, 일반 엔진 워크플로는 다루지 않습니다.

내부 일회성 승인 세션은 정확한 표시 요청을 승인·거부·취소·만료, 외부 해시 서명, 최종 권한 중개기 검증까지 전달합니다. 직렬화한 표시 데이터에는 권한이 없고, 받아들인 승인은 서명이나 최종 검증이 실패한 뒤 다시 사용할 수 없습니다. 아직 이 세션을 쓰는 공개 표시 화면, 영속 서명 키 저장소, CLI 변경 경로, MCP 변경 경로는 없습니다.

비공개 Codex 어댑터는 같은 프로세스의 표시 콜백으로 이 세션을 진행할 수 있습니다. 콜백에는 읽기 전용 표시 데이터와 취소 신호만 주고, 정확한 응답 결합과 서명기·실행 권한 분리는 어댑터가 맡습니다. 프로젝트 초기화와 관리 스킬 설치는 각각 별도 일회성 작업, 승인, 실행 식별 정보, 지속 증거 체인을 사용합니다. 깨끗한 프로젝트는 먼저 초기화한 뒤 두 번째 승인으로 스킬을 설치할 수 있습니다. 실제 호스트 화면이나 MCP 입력 요청 경로는 아니며 공개 변경 명령도 추가하지 않습니다.

핵심 실행부에는 이 경로에서 쓸 수 있는 메모리 전용 비공개 로컬 서명기도 있습니다. 호출자가 직접 건넨 정규 Ed25519 개인 키를 가져와 권한 중개기의 신뢰 공개키를 파생하고, 최대 5분·32회로 제한한 서명기 사용권을 만듭니다. 취소, 만료, 사용 횟수 소진, 복사한 핸들, 명시적 폐기는 모두 안전하게 차단합니다. 키를 자동 생성하거나 키 파일을 읽고 쓰거나 영속 저장하지 않으며 표시 콜백에 키 내용을 전달하지 않습니다.

로컬 호스트 실행부는 정확한 프로젝트 초기화와 관리 스킬 추가를 내구성 있는 실행과 읽기 전용 복구 검사에 연결했습니다. 복구 실행, 증거 재조정, 팩 갱신·제거, 모든 엔진 변경은 아직 호스트 경로에 연결하지 않았습니다.

별도 Windows x64 패키지는 네이티브 격리 산출물 하나를 빌드합니다. 선택형 자체 검사는 폐기 가능한 상태에서 파일 변경, 소유한 로컬 네트워크 수신점 접근, 자식 프로세스를 차단하는지 확인하고 프로세스 수 제한, 종료 정산, 정확한 정리까지 검증합니다. 방금 성공한 동일 프로세스 증명은 경로를 담지 않은 폐기용 스냅샷, 임의 확인값, 고정 호출·출력 해시, 시간·출력 한도, 단일 프로세스, 종료·정리에 묶인 합성 읽기 작업 하나만 허용할 수 있습니다. 성공한 합성 실행 증명은 정확한 읽기 전용 사용자 프로젝트·실행 파일 스냅샷과 짧은 수명의 내부 입장권 하나에 다시 묶을 수 있습니다. 복사한 계획·보고서·증명·스냅샷·입장권·원본 전달 권한은 다시 쓸 수 없습니다.

Godot 목표 버전 보고가 정확히 일치하면 승인에 묶인 비공개 경로가 이 입장권을 한 번 소비할 수 있습니다. 승인된 프로젝트 목록과 실행 파일을 폐기 가능한 루트에 복사하고, 역량이 없는 AppContainer 안에서 고정된 헤드리스 호출 하나를 시작합니다. 경로 없는 프로세스 보고와 `RunReceipt`를 보존합니다. 성공, 제한된 실패, 시간 초과, 호출자 취소를 전용 시험 실행 파일로 검증했습니다. 취소 결과는 프로세스 트리 정산과 폐기 상태 정리가 끝난 뒤에만 반환하며, 원본 프로젝트는 AppContainer 밖에 둔 채 실행 뒤 다시 확인합니다.

이 패키지에는 공개 명령과 MCP 도구가 없습니다. 임의 명령·환경·네트워크 대상·원본 쓰기 권한을 받지 않습니다. 공개 제공자 목록에도 등록하지 않았고, 설치된 Godot 배포본이나 회색 상자 전체 흐름은 아직 검증하지 않았습니다.

## 아직 안 되는 일

설치하거나 배포할 수 있는 패키지는 없습니다. 다음 기능도 아직 제공하지 않습니다.

- 공개 프로젝트 초기화와 스킬 설치
- 공개 팩 추가·갱신·제거·복구·복구 종료
- 실제 승인 화면, 영속 서명 키 저장, 키 교체
- Godot, Unity, Unreal 실엔진 브리지
- 에디터 연결, 씬·자산 변경, 게임 입력, 실행 화면 캡처
- 엔진 테스트, 실엔진에서 검증한 실행 가능한 골든 프로젝트, 빌드·내보내기 실행
- 증거 목록·조회·내보내기와 출시 게시

내부 Godot 탐색·격리 사전 검사 코드가 있다고 해서 지원 상태가 올라가지는 않습니다. 공개 컴파일 격리 제공자 목록은 아직 비어 있습니다. 비공개 경로는 정확한 버전, 별도 승인, 복사본에서 실행하는 고정 헤드리스 호출만 허용하며 전용 시험 실행 파일로만 검증했습니다. 설치된 Godot 배포본, 실제 플레이 화면, 결정적 입력, 실행 화면 캡처, 대상 내보내기 증거가 없으므로 실엔진 지원은 성립하지 않습니다.

## 제품 범위

첫 완성 목표는 Windows x64용 오프라인 싱글플레이 3D 버티컬 슬라이스입니다. 이동, 카메라, 충돌, 수집물, HUD 개수 표시, 저장·불러오기, 승리 상태, 결정적 재생, 테스트, 실제 실행 화면 캡처, 로컬 빌드를 포함합니다.

Godot 어댑터를 먼저 만들고 Unity와 Unreal Engine을 이어서 구현합니다. 에디터가 필요 없는 검사는 Linux CI에서도 실행합니다. 실제 에디터를 확인해야 할 때는 Windows 실행기를 사용합니다.

웹 게임 프레임워크, 멀티플레이, 모바일, 콘솔, XR, macOS 검증, 데스크톱 대시보드, 엔진 자동 설치, 외부 3D·오디오 생성은 첫 알파 범위에서 제외합니다.

## 출시 단계의 의미

현재 버전은 `0.0.0`이며 알파 출시로 표현하면 안 됩니다. `0.1.0-alpha`는 Godot 회색 상자 프로젝트의 전체 흐름을 실행하고 증거까지 보존해야 붙일 수 있습니다. Unity와 Unreal은 각자 같은 흐름을 통과할 때까지 `planned`로 남습니다.

`1.0.0`은 세 엔진 모두 선언된 골든 프로젝트에서 `verified`에 도달하고, 설치 수명주기·롤백·권한·증거·행동 평가 계약이 안정화된 뒤에만 허용합니다.

현재 패키지 표시는 `UNLICENSED`입니다. 패키지를 배포하거나 외부 코드를 포함하기 전에 프로젝트 라이선스를 정해야 합니다.
